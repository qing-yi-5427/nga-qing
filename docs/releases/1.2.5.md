## 源码重建与内容比对

使用 JDK 21、Android SDK、已有 Gradle 缓存运行：

```powershell
.\gradlew.bat --offline --no-daemon :app:assembleRelease :app:testDebugUnitTest --tests '*Favorite*'
.\gradlew.bat --offline --no-daemon :app:clean :app:assembleRelease
```

两次均 `BUILD SUCCESSFUL`。第一次构建含 40 项收藏相关测试，零失败、零错误、零跳过。第二次清理构建的 158 个 ZIP 条目内容及 ZIP 元数据与第一次相同。两次 APK 整体 SHA-256 不同，仅因签名块 ID `0x504B4453` 的填充内容变化；APK v2 签名数据本身相同，应用条目相同。

原包和重建候选均为 2,319,009 字节，各有 158 个同名 ZIP 条目；其中 156 个解压内容相同，包括 `AndroidManifest.xml`、`resources.arsc`、资源和原生库。差异仅在：

- `classes.dex`：原包 3,946,840 字节；重建候选 3,946,820 字节。DEX 定义计数相同，但反汇编比对发现一个经 R8 混淆、映射到 Compose `PostScreen` 的方法存在指令差异，重建版少 5 条指令。这是实际代码载荷差异，不能归类为时间戳或签名差异。
- `assets/dexopt/baseline.prof`：原包 4,830 字节；重建候选 4,832 字节。

原包的历史构建日志显示 Kotlin 编译和 R8 曾重新执行，但无法仅凭日志还原当时构建输入。因此，本报告不把原包声明为精确提交的可复现产物。重建候选直接来自指定提交，且两次构建的应用条目一致。
